# Compliance checklist

Checklist from `docs/PLAN.md` §6. Each item states how this repository satisfies it today, and what
is still open. Status: **done** (enforced in code or tests), **process** (team discipline, no code
check possible), **open** (needs a decision or an organiser answer).

Team decision (Oct 25 2026): the only data about BAR-ATH is the provided data. Open data about
**other games** (DFL/Sportec CC BY 4.0, SkillCorner MIT) is used for validation and parameter
learning, as RULES.md allows; sources, licences and preprocessing are in `docs/EXTERNAL.md`. Nothing
in the code fetches anything at runtime.

## Process notes

Notes on process that are not parameters fitted on BAR-ATH labels. Nothing below is a label, a
correction or a frame-specific constant.

1. Public ground truth. No number is fitted, tuned or
   selected on BAR-ATH labels. The v1 to v2 public change (spellF1 0.548 to 0.594, 17 spells) is
   within noise and was not used to choose v2.
2. Label-free diagnostics of our match (Smart Tagging set-piece windows, restart team, phase-team
   agreement). Until 2026-11-03 they served as tie-breaks between candidates tied on external CV
   (`docs/DEADBALL.md`, "Full-run results and decision" and "Switch prior on top of (c) + touch").
   From 2026-11-03 they are an alarm only.
3. Label-free statistics of our tracking: the cleaning parameter `max_gap_frames` and the
   degradation of external matches (`external/degrade.py`, gap-length statistics of our ball gaps)
   come from our match's tracking, never from its labels.
4. Minor cross-validation leak: the cleaning parameters (`reference_params`, `reference_stats`;
   `src/possession/external/prepare.py`, `bounds.py`) are computed on all 7 DFL matches, including
   the held-out fold's match. Label-free, affects only the DFL external CV, documented in
   `docs/PARAMETERS.md` ("Cleaning parameters"). Not changed.

`possession.evaluate` defaults to the public ground truth. It is for pipeline sanity checks only,
never for comparing variants.

## Label contract

- Graded frames (11,185–90,651 and 110,808–190,197) always get H, A or D. `submit.finalize_labels`
  raises if a graded frame carries anything else, including X.
- Ungraded frames get X through `finalize_labels`. The baseline does not use it, so that its output
  stays byte-identical to the official `baseline_smooth50.csv`. `configs/rules.json` sets
  `finalize: true`.
- The `rules` method writes an explicit D on every graded frame before each half's detected kickoff,
  which covers the second-half pre-kickoff block (FAQ). The `learned` method forces D through the official kickoff anchors from `games.py` when
  `force_prekickoff_dead` is true (the default). External matches never go through this step.
